# Porch & Party Authority Scale Operating Contract

Effective: 2026-07-24

## Objective

Maximize the probability of reaching 100,000 verified external citation events within 180 days or less as an aggressive stretch target, not a guarantee.

The system never equates fanout opportunities, page count, indexing, impressions, LLM mentions, or backlinks with verified citations.

## Operating loop

1. Materialize a compressed 100K deterministic opportunity runway across real Porch & Party services, declared service areas, buyer intents, formats, audiences, and stages.
2. Rotate a 2,500-opportunity operational window.
3. Score opportunities against existing public authority routes.
4. Prefer improving an existing intent-matched route over creating a duplicate URL.
5. Publish only enriched query-universe entries explicitly placed in the governed queue.
6. Apply the evidence-gated daily ceiling: 3 → 5 → 10 → 15 → 25 → 50. These are ceilings, never quotas.
7. Admit and freeze accepted public authority outputs.
8. Validate sitemap and distribution inputs, then use IndexNow and Search Console when configured.
9. Record external evidence separately and let observed yield determine whether velocity may change.

## Twin boundary

Twin Agent is **not installed in this repo**. Twin remains limited to Velocity and Spry. Porch & Party uses only generalized page-quality lessons demonstrated by Twin: answer-first summaries, exact-intent headings, explicit comparisons, extractable checklists/frameworks, meaningful use cases, and improve-before-duplicate-new-URL decisions.

## Local truth boundary

Geography is limited to `data/service_areas/areas.json`. The authority engine may not invent service locations, customer projects, reviews, prices, rankings, or external citations.

## Core commands

- `npm run authority:cycle` — full governed local authority cycle.
- `npm run validate:release` — canonical release validation.
- `npm run authority:scale:status` — freeze/admission status.
- `npm run distribution:prepare` — deterministic IndexNow/GSC input preparation; does not contact providers.
- `npm run search:intelligence` — non-publishing search-intelligence baseline snapshot. Live search observation and GSC truth run only when credentials and explicit live flags are present; unavailable or degraded providers are recorded as such.

External distribution runs only through the distribution workflow or an explicitly configured local invocation.

## Search intelligence truth boundary

The search-intelligence lane does not alter publishing cadence, queue admission, or accepted-output freeze state. It prepares observation, diagnosis, bounded repair candidates, and same-query retest evidence for existing approval and publishing rules.

Google Search Console is the authority for own-site Google performance when credentials are configured. Bing/live-search observations and Gemini/search grounding, if later configured, are observation lanes only and must not be represented as literal Google SERP rank.
